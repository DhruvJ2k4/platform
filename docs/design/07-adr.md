# 07 · Architecture Decision Records
**Summary:** Append-only record of every major decision, including superseded ones. **Purpose:** preserve rationale; prevent re-litigating settled questions without new evidence. **Format:** Problem → Alternatives → Decision → Trade-offs accepted → Future implications. Statuses: ACCEPTED / SUPERSEDED-BY.

**ADR-000 Constraints charter — ACCEPTED.** Problem: scope discipline. Decision: cost ≤ ₹1,000/mo; maintenance ≤ 2 hrs/wk; EOD-only; human gate architectural; every ML component must beat a rules baseline; CUT list (social sentiment, option flow, news NLP, online learning/RL) binding. Implication: all other ADRs inherit these tests.

**ADR-001 System of record = official exchange archives (bhavcopy + CA + filings) — ACCEPTED.** Alternatives: broker candles (survivorship-biased), paid vendors (cost-ceiling breach: 0.3–0.8%/yr drag), yfinance (unreliable). Trade-off accepted: we own parser maintenance across format epochs. Implication: raw hoarding forever; parsers are format-epoch-versioned.

**ADR-002 PIT fundamentals: forward XBRL collection + lag-stamped historical bridge + snapshot-site validation oracle — ACCEPTED.** Alternatives: any single provider (all fail PIT or cost). Implication: fundamental factors gated ≥ 8 quarters native PIT; bridged rows flagged and stress-tested (+30d lag stretch).

**ADR-003 Storage: Parquet canonical + DuckDB as (stateless) query/build engine — ACCEPTED.** Alternatives: Postgres/Timescale (ops burden), SQLite (poor columnar). Implication: zero database operations; scale ceiling ~100× current needs.

**ADR-004 Orchestration: cron + idempotent, date-parameterized CLI jobs — ACCEPTED.** Alternatives: Airflow/Prefect/Dagster (services without justification at 5-step daily DAG). Revisit trigger: DAG genuinely exceeds ~15 interdependent steps.

**ADR-005 Backtesting: custom small engine + vectorbt as cross-validation oracle — ACCEPTED.** Alternatives: zipline (dead once already), backtrader (maintenance mode), Lean (overkill). Rationale: Indian cost/tax/PIT/delisting fidelity *is* the complexity; frameworks supply everything except it. Trade-off: we own bugs → doc 16's golden/property/oracle program. **Amended by ADR-016:** the "engine" is the shared portfolio engine; backtesting is a driver.

**ADR-006 Universe: NSE-only, EQ series; BSE-ready via ISIN-keyed master + adapter slot — ACCEPTED.** Alternatives: NSE+BSE now (≈1.8× ingestion surface for <5% investable additions concentrated in fraud/illiquidity territory). Amendment (V2): BE/BZ/SME series structurally excluded, not merely liquidity-filtered.

**ADR-007 Liquidity/capacity: participation-based investability (position ≤ p_max·MDTV), tiered base-slippage + √participation impact, turnover governance via buffers — ACCEPTED.** Alternatives: static "top-N by mcap" universes (ignores order size; not corpus-portable). Implication: identical model in both drivers; recalibrated from real fills (ADR-017).

**ADR-008 Historical index constituents never used in logic — ACCEPTED.** Problem: membership files are current-state (look-ahead). Decision: universes from own PIT ranks; official indices consumed only as TRI return series. Implication: benchmark ingest adapter for TRI values.

**ADR-009 Deployment: home mini-PC on residential IP + external dead-man switch + encrypted cloud backup — ACCEPTED.** Alternatives: VPS/GitHub Actions ingestion (datacenter-IP hostility; validated as P0 spike), laptop (not always-on). Trade-off: home power/ISP risk, healed by idempotent catch-up + retro-downloadable feeds.

**ADR-010 Stack: Python 3.12+/uv/pandas-at-edges/DuckDB-for-transforms/pydantic-configs/Typer/pytest+hypothesis/ruff/structlog/Jinja2-static-HTML — ACCEPTED.** Banned absent new ADR: Airflow, Spark, Kafka, K8s, microservices, feature-store products, vector DBs, LLMs in the decision path.

**ADR-011 BrokerPort: manual-first thin port; Kite → others as adapters — ACCEPTED.** Implication: fills loop back into slippage calibration; Kite daily-token friction documented, defers automation.

**ADR-012 Strategy books; swing gated by pre-registered admission (core live ≥ 4 quarters; swing go/no-go with full friction + T+1 latency; ≤ 20% capital; −15% kill switch) — ACCEPTED.** Alternatives: unified multi-horizon process (contamination), refusal (paternalistic). Implication: `book_id` first-class everywhere.

**ADR-013 Curated snapshot versioning — SUPERSEDED-BY ADR-016.**

**ADR-014 Dynamic N + minimum viable corpus (N∈[12,30]; pos ≥ max(₹25k, flat-fees/10bps); < ₹3L → index-core degraded mode; < ₹1L → refuse direct equity) — ACCEPTED.**

**ADR-015 Agent-ready, not agent-driven: typed CLI tools + logged decisions now; agent admission ladder (narration → research assistant → decision support → authority via champion/challenger only) — ACCEPTED.** Decision cadence remains EOD; live quotes are an execution detail.

**ADR-016 One portfolio engine, two drivers; reproducibility by rebuild — ACCEPTED (V2 keystone).** Problem: sibling backtester/engine invites research-live skew; snapshot hoarding conflated reproducibility with storage. Decision: pure `decide()` shared by replay and live drivers; curated is disposable/rebuildable from immutable raw + git; only champion runs pin materializations; run manifests record (code hash, config hash, raw watermarks). Trade-offs: rebuild time on old runs (minutes — acceptable); engine purity discipline required (lint-enforced). Future implication: any new decision logic lands once, is backtested and shipped as the same object.

**ADR-017 Reconciliation loop: contract notes parsed, modeled-vs-actual > 5bps investigated, slippage params recalibrated after ≥30 fills — ACCEPTED (V2 addition).**

**ADR-018 Incubation: challengers run paper-only ≥ 1 quarter post-gauntlet before capital — ACCEPTED (V2 addition).** Rationale: the missing rung between backtest and money; costs one quarter of patience, buys a live out-of-sample sample.

**ADR-019 Index-reconstruction acceptance amended to a two-part test — ACCEPTED (implementation planning finding).** Problem: the frozen ≥0.999 correlation criterion silently required historical constituent weights, which ADR-008 correctly bans as look-ahead. Decision: Part A — 50 largest corporate-action events spot-checked vs. independent source, |diff| > 25 bps fails; Part B — equal-weight proxy of current Nifty50 constituents, 5y daily-return correlation vs official TRI ≥ 0.995 with zero unexplained >5% single-day divergences. Trade-off: slightly weaker breadth statistic, honest method. Affected docs updated: 13 (F2), 18 (P0 exit), 21 (§14). Lesson: acceptance criteria get a "is this measurable without banned data?" check at freeze time.

**ADR-020 Import package is `quant`; the name `platform` stays for repo, CLI, and distribution — ACCEPTED (P0-01 finding).** Problem: doc 20's skeleton named the import package `platform`, which Python's stdlib shadows — the stdlib directory precedes site-packages on sys.path, and pytest preloads stdlib `platform` into sys.modules, so `platform.engine`/`platform.cli` could never be imported (verified empirically before any code existed). Alternatives: sys.path front-insertion hacks (fragile; break stdlib consumers inside test runners), renaming repo/CLI/product too (needless churn). Decision: import package `src/quant/`; repo directory, `platform` CLI command, and distribution name unchanged; doc 20 skeleton and CLAUDE.md paths updated in the same pass. Trade-off accepted: import name differs from the product word. Implication: candidate top-level module names get a stdlib-collision check at design time (`python -c "import <name>; print(<name>.__file__)"`).

**ADR-021 Contract layer: pandera models in `quant.schemas`, SQL DDL in `schemas/`; Arrow is the canonical typed read; DECIMAL always explicit — ACCEPTED (P0-02 finding).** Problem: doc 20 placed importable Python contracts in the non-package `schemas/` directory; DuckDB's pandas export (`.df()`) silently degrades DECIMAL to float64, violating money-is-Decimal at the contract boundary; and bare `DECIMAL` silently means DECIMAL(18,3). Alternatives: a second installed top-level package (build-backend gymnastics, generic import name), models kept uninstalled in schemas/ (unimportable). Decision: authoritative DDL in `schemas/*.sql`; importable models in `quant.schemas` as the bottom layer, importing no platform code and no duckdb (keeps engine's transitive purity clean); canonical read = `to_arrow_table().to_pandas(types_mapper=pd.ArrowDtype)` pinning decimal128(p,s); every DECIMAL carries explicit (p,s), test-enforced. Trade-offs accepted: doc-20 tree comment amended; arrow-backed dtypes become a hard dependency of the validation gate. Implication: `.df()` is banned for money-bearing reads; DuckDB reserved words (`order`, `asof`) are quoted in DDL; contract changes stay additive per doc 10's migration policy.

**ADR-022 Security master: observations-first construction, open-past listings, identity-only resolution — ACCEPTED (P0-09 finding).** Problem: the classic-11 bhavcopy era carries no ISIN, so historical (symbol, series) rows need an effective-dated identity map; but the NSE symbol-change file is a current snapshot, renames can predate all ISIN-bearing observations, and probes falsified two assumptions (an ISIN legitimately trades one symbol in MULTIPLE series the same day — EQ+BL/EQ+T0; the live symbolchange.csv has NO header row and contains self-rename artifact rows). Alternatives: sentinel start dates (fabricated facts), file-first construction (a snapshot row could re-map observed trading days), refusing pre-observation resolution (defeats the resolver's purpose for pre-2011H2 data). Decision: bhavcopy observations win; the symbol-change file only pins rename boundaries whose full path lands inside an observation gap — including MULTI-HOP paths through never-observed intermediate symbols (IPAPPM→ANDPAPER→ANDHRAPAP on sparse sample days), which emit exact synthetic intermediate eras; every record used is CONSUMED (a rename record is explained at most once, by the earliest-observed ISIN — pins and chains share one global ledger, so an ISIN change cannot let the new ISIN steal the old one's history) and backdates pre-observation chains (nearest-predecessor links, strictly-decreasing dates, ties → ContractViolation); fallback boundaries end/start at observations with unowned gap days resolving to None (miss beats guess); the oldest era of every chain — and never-renamed ISINs — gets `valid_from` NULL = open past (schemas/listing.sql widened from NOT NULL; doc 10 mirrors the convention); recycled symbols are repaired in three deterministic passes — synthetic claims yield to any ISIN's observations, then under conflict the EVIDENCE-EARLIER row keeps its head and retreats its unobserved tail while the later row retreats its unobserved head (paper bounds never override another ISIN's observations), then any surviving overlap raises ContractViolation, as does a genuine observed same-day cross-ISIN conflict; overlapping symbol spans of the SAME ISIN are real in official data (a bond published one day under its issuer's renamed equity symbol inside its own span) and are not an identity ambiguity — they become evidence-bounded parallel eras, counted and logged, never fatal; file-backdated synthetic claims yield to ANOTHER ISIN's observations too (clipped to start after the other's last observation, or dropped when fully falsified — the ISIN-change case, e.g. AARVEEDEN across INE273D01019→INE273D01027): observations win globally; the PREVCLOSE splice DQ compares only (near-)adjacent boundaries (≤7 calendar days) — wider gaps are incomparable, not failures; `security.name` is display-only (current name is anachronistic for historical text joins); doc 21 §4's candidates line is amended to price-row-anchored candidates. Trade-offs accepted: listing answers IDENTITY only — never existence, age, or activity (hard requirement on P0-13; age/existence come from price rows); a pre-2011 recycled symbol with no rename record can mis-resolve (PREVCLOSE splice DQ counters are the early net, P0-19's two-part validation the full one); companies dead before classic-13 ISIN coverage (~2011-07) are unresolvable — pre-2011H2 cross-sections are survivor-conditional and cannot support performance claims; ISIN treated as immutable identity (reissue events sever chains → conservative exclusion). Implications: build emits a stats report (open-past/synthetic/fallback/clip/splice counters) so exposure is measured, not described; snapshot-truncation invariance is property-tested (a build from inputs ≤ D resolves every observed row ≤ D identically — identity resolution cannot leak the future); symbolchange re-fetch rides the P0-17 nightly list, never operator memory.

**ADR-023 Corporate actions: cookie-primed www JSON API source, free-text classifier, conservative available_at, `other` review bucket, rights→review — ACCEPTED (P0-10 finding).** Problem: doc 09 listed the CA feed only as Core/"File/portal" (P0-05 never resolved it), the P0-05 verdict implied the www API needed a browser-grade client (deferred to P0-21), and the `corporate_actions` contract's six-kind enum plus doc 21 §1's `num:den`/`b:a` notation left column semantics and the review boundary underspecified. Live probe (2026-07-15, ≤7 residential requests) falsified the assumptions: no bulk CA file exists on the tolerant host; the www API is COOKIE-gated not TLS-gated (homepage 403 sets the Akamai cookie, then the API returns 200 to a plain client); the window is uncapped (5y in one call, 12,182 rows); `caBroadcastDate` is null for every row; `faceVal` is anachronistic (the current, post-split value — 251/263 splits — not the value at ex_date); and `subject` is human-entered free-text with typos and rare compound/non-equity-instrument cases. Alternatives: browser-grade client now (unnecessary complexity, P0-21 scope creep — falsified); derive split ratios/rights S from faceVal (anachronistic → wrong factors); force ambiguous reorganizations into `kind=demerger` (a semantic lie that also mislabels amount-less dividends); auto-classify rights from feed terms (silently wrong factor when a name split after its rights issue); available_at=fetch-time (hides all historical CA from any backtest whose asof precedes the fetch). Decision: adapter cookie-primes (SourceSpec.prime_url; the prime 403 is tolerated, not gated) then fetches an uncapped window, storing raw JSON via RawStore under logical_date=until; a conservative classifier maps `subject`→kind with pinned column conventions (split ratio_num/den = old/new face value from subject text → factor den/num, covering consolidations; bonus ratio_num/den = X:Y → factor den/(num+den); dividend cash = Σ per-share amounts summed over compounds; buyback auto; demerger + capital-reduction + compound-scheme + unclassifiable-non-meeting → `other`; pure meetings dropped-and-counted), with content ambiguity always routing to needs_review (never a crash — only structural JSON drift is a ParseError) and nothing price-affecting ever silently dropped (the fallthrough is other/needs_review); an additive seventh kind `other` is added (pandera enum + doc-10 comment; schemas/corporate_actions.sql has no CHECK so no DDL change); rights are ALWAYS needs_review (anachronistic faceVal ⇒ issue price S unrecoverable, P_cum unknown at ingest); available_at = ex_date (00:00, naive), look-ahead-safe; non-equity instruments (series GS/IV/RR) are excluded from the equity CA table by an exclude-list (so a real equity CA tagged non-EQ is never dropped — CAs are ISIN-level facts); doc 21 §4/§6's hard-exclusion "pending demerger review" is generalized to "any status=needs_review CA" so `other` and rights also block curation. Trade-offs accepted: rights (~40/yr) and `other` (~1/yr) become operator review items rather than auto factors (stale-but-consistent beats fresh-but-wrong); a preference-share bonus ("Bonus Ncrps") is routed to review, not auto (a false equity dilution otherwise); available_at is coarse until P0-21 mines broadcast timestamps; compound dividends are summed into one row (per-component detail deferred to P0-12 if needed). Implications: the builder emits a stats report (per-kind, drops, auto/needs_review) so exposure is measured; the P0-11 adjuster consumes the pinned conventions and must block any needs_review ISIN; the SourceSpec cookie-prime shape is reusable for other cookie-gated www endpoints; the CA re-pull rides the P0-17 nightly window.

**ADR-024 Curated publish: versioned dirs + CURRENT pointer, resolutions-in-config, pre-ex-window block, CA coverage bounds, equity include-list, exact-Fraction factors — ACCEPTED (P0-11).** Problem: P0-08/09/10 returned validated frames with persistence deferred; the adjuster needed five unspecified mechanisms settled — where operator demerger/rights factors live (a DB row would be wiped by every rebuild), what "curation of affected ISIN blocked" (doc 06) means physically versus doc 12's "unresolved window", how the P0-10 coverage-floor carry becomes enforceable, how bhavcopy's parallel series rows fit prices_adj's (isin, d) PK (P0-09 breadcrumb), and how "golden to the paisa" coexists with doc 21 §1's return-invariance (probes falsified the naive readings: the vault census found 162 distinct series so an exclude-list is unmaintainable; hypothesis found that paisa-quantized closes CANNOT satisfy bit-exact return invariance — independent half-paisa roundings perturb ratios, e.g. 100/3→33.33 vs 101/3→33.67 ≠ 101/100). Alternatives: operational-DB resolution rows (breaks curated = f(raw, code, config), doc 08); whole-ISIN blocking (strips ~250 ISINs' provably-correct post-ex history; operator-rejected); publishing all 162 series "adjusted" by an equity-only CA table (fresh-but-wrong for IV/RR/bond CAs); float cumulative factors (paisa drift); storing adjusted prices at higher precision (doc 10 freezes DECIMAL(12,2)). Decision: operator resolutions live in config/ca-resolutions.yaml keyed (isin, ex_date, kind), ratio columns keep the ROW KIND's semantics (split/rights/demerger/other → factor den/num; bonus → den/(num+den)); an unmatched or ambiguous resolution is a ConfigError; blocking is the PRE-EX WINDOW — any pending needs_review action at E withholds that ISIN's prices for d < E (post-ex rows are provably unaffected; the latest pending E governs); CA coverage bounds gate adjustability — floor = min parsed ex_date, ceiling = max fetch-window end; price dates outside [floor, ceiling] are excluded + counted, never partially adjusted; prices_adj holds the EQUITY family only via include-list EQ>BE>BZ>SM>ST>SZ with the highest-priority series as the one (isin, d) row (auxiliary window rows BL/T0/BO/IL and bond/unit series excluded + counted; duplicate same-series rows = ContractViolation); cumulative factors are exact fractions.Fraction products — adjusted o/h/l/c = quantize(raw × F, paisa, HALF_UP), adj_factor stores float(F), volume/traded_value/close_unadj stay raw (liquidity math is adjustment-invariant); doc 21 §1's return invariance is EXACT on the factor path (close_unadj × adj_factor) and holds on quantized closes only within deterministic half-paisa rounding — features needing exact long-horizon returns consume the factor path; publish writes immutable data/curated/versions/<run_id>/ (parquet; prices_adj hive-partitioned by year, sorted (isin, d)) with manifest.json digesting the doc-08 identity (raw watermarks, code ref, config hashes, asof), run_id = curate-{asof}-{shorthash(identity)} — wall-clock-free — and consumers switch via the one-line CURRENT pointer swapped with os.replace (atomic; stale-but-consistent under any crash); an existing run_id re-verifies byte-identity (mismatch = determinism breach → ContractViolation) and republishing is a no-op. Trade-offs accepted: pending reviews (rights-heavy, ~196 ISINs live) hide pre-ex history until resolved — measured in stats, resolved via RB-4; coverage bounds currently limit published prices to ≥2021-07-15 until P0-19 backfills deeper CA history; quantized closes carry up to half-paisa rounding (exact path provided); curate --incremental deferred (rebuild is the correctness path). Implications: features (P1-05) compute returns from close_unadj × adj_factor; the golden 3-stock/8-quarter scenario seeds tests/golden/golden_scenario.py and P1-03 extends it with tax lots; P0-13's universe consumes read_current(); P0-16's DQ suite extends the publish gate; P0-17 pairs nightly CA pulls with bhavcopy so the ceiling tracks fresh prices; P0-19 revisits the floor.

**ADR-025 Dividend cash resolutions: `kind='dividend'` entries in config/ca-resolutions.yaml carry `cash_amount` (that row's per-share amount), never ratio terms — ACCEPTED (P0-12 finding).** Problem: the P0-12 dividend cash surface credits only rows with a parseable amount, and the live table carries 16 needs_review dividends (amount-less/malformed subjects — "Interim Dividend", "Interim Dividend Rs - 20 Per Share") that can never credit AND block their ISINs' pre-ex price windows under ADR-024's generalized needs_review block — while CAResolution was ratio-only (strictly-positive ints required), so RB-4 had no emptying mechanism for them: permanently blocked windows flowing into P0-13's universe. Alternatives: defer wholesale to P1-03 (16 blocked windows propagate into universe/liquidity stats meanwhile); parse harder (the subjects genuinely lack usable amounts); a dividend table with row-level review semantics (rejected this pass — doc 10 stays at 15 tables, P0-12 shipped as a derived surface). Decision: CAResolution is shape-per-kind — ratio kinds carry ratio_num/ratio_den and never cash; dividend carries cash_amount (strictly positive, paisa-quantized, DECIMAL(12,2)-bounded Decimal; sub-paisa, oversized, unknown-kind, and binary-float inputs all rejected loudly at load) and never ratio; the amount is THAT ROW's per-share figure as disclosed on or before ex_date (compound components summed per ADR-023), never the ex-date group total — same-day payable rows sum downstream, and the build warns when a resolved dividend has payable same-key siblings; `_apply_resolutions` fills the kind's column, leaves the other untouched, and flips needs_review → resolved under the unchanged exactly-1-match rule; a resolved dividend credits through build_dividend_cash like any auto row, stops blocking the pre-ex window, and still never price-adjusts (action_factor stays None for dividends); the credit surface enforces available_at <= ex_date at derivation so a P0-21 broadcast-timestamp refinement trips loudly instead of leaking. Trade-offs accepted: equal-amount AMBIGUOUS dividend groups are out of this mechanism's reach by design (their rows are auto, not needs_review — carried to P1-03 unchanged), and a resolved amount that collides with an equal payable sibling degrades the group to ambiguous (conservative exclusion + warning; RB-4's post-rebuild stats check surfaces it — no disambiguation mechanism until P1-03); preference/cumulative-dividend review rows must never credit equity cash and so have NO resolution shape (none among the 16 live rows; P1-03 owns a no-effect shape if one appears); two needs_review dividends sharing one (isin, ex_date) key would be unresolvable under exactly-1 (none live: the 16 rows sit on 16 distinct ISINs); filing the 16 real resolutions is operator work against circulars (RB-4), batched BEFORE any P0-13/universe results exist so resolution state is never result-conditioned. Implications: ca-resolutions.yaml documents both entry shapes and the row-not-total rule; RB-4 (doc 17) gains the dividend-specific verify step (credit present at the circular amount, ambiguous_rows unchanged — the chart check proves nothing for cash); docs 06/12/21 name amount-less dividends in the needs_review enumeration; doc 20's P0-12 row is annotated with the derived-surface reading.
